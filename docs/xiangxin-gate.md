# 象信 AI 前置闸门 —— 医药政策雷达接入说明

**日期**：2026-11-25
**改动范围**：新增 `src/xiangxin_gate.py`、`src/score.py`、`config/scoring.yaml`、`.github/workflows/radar.yml`

---

## 一句话

象信**不替代** LLM 打分，而是做 LLM 前面的闸门：拦掉明显不是政策的内容
（融资并购 / 临床读出 / 股价 / 人事 / 科普 / 招聘榜单），省 LLM 调用。

---

## ⚠️ 判据与另外两个雷达【完全不同】，不要照搬

| 雷达 | 闸门问的问题 |
|---|---|
| pharma-bd-radar | 「有没有交易对手方」 |
| clinical-data-radar | 「有没有具体的临床试验结果或关键节点」 |
| pharma-policy-radar（本雷达） | 「是不是官方机关发出的、对行业有约束力的文件」 |

### 本雷达「是政策」包含的范围（口径对齐 `SYSTEM_PROMPT` 开头的「先判断」段）

1. 机关发布的文件、公告、通知、征求意见稿、目录、集采规则、处罚决定
   （法律/条例/部门规章/规范性文件/指导原则/医保目录与支付规则）
2. 上述文件的**官方解读**（答记者问、政策吹风会、官方图解、官方解读文章）
3. 各级医保局 / 卫健委 / 药监局 / CDE / 国家组织药品联合采购办公室 /
   FDA / EMA / 美国 HHS / CMS 发出的**政策类文件**
4. 面向行业征求意见、公布实施日期/过渡期安排
5. 官方对医保待遇、药品定价、集采规则、注册审评流程的说明性文件

**「非政策」**包括：企业融资/并购/授权交易、临床试验数据读出、
**单个药品或器械的批准**（`FDA Approves…`、NMPA 批件公示）、
股价/财报、人事、会议通知/培训/征稿/招聘/榜单、
行业综述/软文/科普、企业产品推广、纯转载通稿。

---

## ⚠️ 闸门的职责边界（重要，别让它越界）

本雷达的闸门**只回答「是不是政策」这一个原子问题**。

它**不**判断：
- 发文机关在不在白名单（`scope.py` 和 LLM 的活）
- 影响范围够不够大（省 / 国 / 单个地市）
- 文件是不是事务性文件（参比制剂目录、转 OTC、说明书修订）

**理由**：本雷达单日候选可达 500+ 条，省级文件占很大比例。
闸门如果连"机关白名单"一起判，很容易把省级政策误杀——
那是本雷达的正常产出，不是噪声。

> 类比：闸门是"是不是政策"的粗筛，scope.py 是"是不是本雷达该做的政策"的细筛，
> LLM 是"值不值得写"。三层职责不能混。

## 改了什么

### 1. 新增 `src/xiangxin_gate.py`

独立模块，只做一件事：判断「这条是不是政策」。

**安全边界（全部实测过）**：

- 无 `XIANGXIN_API_KEY` → 全部放行
- 没装 `xiangxin-sdk` → 全部放行
- key 无效（401）→ **整体旁路**，只打一次请求就退出，不浪费 401
- 单条失败 → 只放行那一条，其余继续
- **空 state（标题/摘要/正文全空）→ 不判，直接放行**（见下方 bug 记录）
- 配置关闭 → 完全不生效

### 2. `src/score.py`

`score_items()` 里接闸门，在 `_prefilter` 之后、送 LLM 之前。

### 3. `config/scoring.yaml`

新增 `llm.xiangxin_gate.enabled`，**默认 true**。

## 🐛 踩过的坑：空 state 被误判成「非政策」（已修）

### 症状

首次回归测试报出漏杀，逐条查下去发现漏杀的条目
`title` / `summary` / `content` **全部为空**——正文抓取失败时只剩 `id`。

送进象信时 state 是：

```python
{"标题": "", "摘要": ""}
```

**两个空字符串**。象信没有任何文本可判，只能猜——而它**一律猜成「非政策」**。

### 根因

同源问题在临床数据雷达上先暴露（43 天历史数据里 10 条 score≥6.0 的真实读出被误杀），
本雷达与 BD 雷达是同一个架构，同一个坑。

### 修法

加 `_has_text()`：**没有文本就不判，空条目直接放行给 LLM**。

```python
if not _has_text(it):
    stats["no_text"] = stats.get("no_text", 0) + 1
    passed.append(it)
    continue
```

理由：空条目反正也拿不到素材（compose 阶段的 `material_too_thin` 会拦），
但**至少不会在闸门这层被误杀成"非政策"**。

### 同源隐患已同步修复

- `clinical-data-radar/src/xiangxin_gate.py`
- `pharma-bd-radar/src/xiangxin_gate.py`（2295 条历史数据里 6 条空 state，
  当时没造成漏杀，但那是运气不是设计）

> **教训：任何交给模型判断的闸门，都必须先确认"有东西可判"。**
> 空输入 + 模型 = 必然误判，且误判方向由模型的默认猜测决定。

## 实测数据

### 自测样例（6 条）

```
总 6 → 放行 3，拦掉 3
  放行: a 国家医疗保障局关于印发《全民医疗保障"十五五"规划》的通知
  放行: b 某省医疗保障局关于印发《XX省职工医保门诊共济实施办法》的通知
  放行: c 国家药监局关于发布《化学药品创新药上市申请前会议药学共性问题指导原则》的通告
  拦掉: d 礼来以 2 亿美元首付款获得诺诚健华 BTK 降解剂全球权益
  拦掉: e 默沙东 TROP2 ADC 胃食管腺癌三期总生存达标
  拦掉: f 某医药公司招聘销售代表若干名
```

国家级、省级、指导原则三类政策全部放行；BD 交易、临床读出、招聘全部拦掉。

### 集成路径实测

用打桩 LLM 跑真实 `score_items()`：

```
[score] 预筛后 2 条（原始 5）
[xiangxin-gate] 拦掉 1/2（50.0%）非政策条目，剩 1 条送 LLM
```

- `p1` 国家级政策 → 放行 ✓
- `p2` 省级政策 → 被 `scope.in_scope` 预筛拦掉（**不是闸门拦的**，层次正确）✓
- `p3` BD 交易 → **闸门拦掉** ✓

### 漏杀验证（最关键的指标）

22 天历史数据，3580 条。正例按 LLM 打分划线。

| 阈值 | 漏杀 |
|---|---|
| score ≥ 7.0 | **0** |
| score ≥ 6.5（生产 keep 线） | **0** |
| score ≥ 6.0 | **0** |
| score ≥ 5.0 | **1** |

拦截 677 条（18.9%），空 state 跳过 13 条。

唯一一条 score≥5.0 的漏杀是「山西省医疗卫生机构综合服务中心关于开展 2026 年
公立医疗卫生机构医用设备省级集中采购市场调研的公告」（score 5.2）——
集采规则形成的前置文件，LLM 自己也只给了 5.2 分（远低于 6.5 keep 线）。

## 🐛 踩过的坑：判据里"像不像通稿"会误杀官方解读（已修）

### 症状

第一版判据的「非政策」栏写了：

> "纯转载通稿、新闻报道（非官方解读）"、"企业产品介绍、推广、招商"

结果**官方自己发的政策解读文章**被判成非政策。实测漏杀 **13 条**，
全是真的政策：

| 条目 | score | flags |
|---|---|---|
| 各地医保持续调整优化医疗服务价格 | 6.7 | `national, price` |
| 口腔医用耗材集采接续启动，预计年底前完成 | 5.6 | `national, price, procurement, stale` |
| 新疆推行 DRG/DIP 半年清算机制 释放医保基金使用综合效能 | 5.6 | `effective, local, price, reimbursement` |
| "医保钱包 2.0"上线 广东职工医保个人账户可以跨省共济使用了 | 5.0 | `national, reimbursement, effective` |
| 国家医保局公开征集立项指南落地执行具体问题 | 5.2 | `consultation, national, price, reimbursement` |
| 省医疗保障事务中心关于公布新增省本级医疗保障定点医药机构的通告 | 5.9 | `formal, local, reimbursement, approval` |

### 根因

判据试图用**文体特征**（像不像通稿）来判断是不是政策。
但**官方发的解读、进展、落地报道本身就是政策的一部分**——
文体特征和内容性质是两回事。

### 修法

判据改成按**发布主体 + 内容性质**判断：

- 「非政策」栏删掉"纯转载通稿、新闻报道（非官方解读）"这类**文体判断**
- 「是政策」栏补上第 ⑥ 类：**官方发布的政策落地进展/实施动态/价格调整/
  清算机制/支付方式改革/集中采购接续/定点机构公布**
- 补上第 ⑦ 类：官方对医保钱包等便民服务的上线说明、
  对药品目录立项指南落地执行问题的公开征求意见
- 判据措辞从"是不是政策文件"放宽为"是不是官方机关发布或解读的、
  对行业有约束力或指导意义的政策内容"

### 效果

| | 拦掉 | score≥5.0 漏杀 | score≥6.0 漏杀 |
|---|---|---|---|
| 调优前 | 899（25.1%） | **13** ❌ | **3** ❌ |
| 调优后 | 677（18.9%） | **1** ✅ | **0** ✅ |

调优后负例的置信度也更干净：BD 交易 / 股价 / 临床读出 / 招聘
全部是 `conf=1.000`，判得很死。

> **教训：判断"是不是某类内容"，要用内容性质，不能用文体特征。**
> 官方通稿和媒体通稿在文体上没区别，区别在**谁发的、说的是不是规则**。

## 上线建议

**当前默认 `enabled: true`。**

1. 先观察 1–2 天，记录每天的产出条数、≥6.5 条数作基线
2. 重点看：
   - ≥6.5 的条目有没有变少 → 变少说明有漏杀，要调低 `BLOCK_CONFIDENCE`
   - 产出条数有没有异常下跌 → 检查 `[xiangxin-gate]` 日志的拦截率
3. 若 2 天内 ≥6.5 条数完全一致，再长期开启

**回滚**：把 `enabled` 改回 `false` 即可，无需回滚代码。

## 已知局限

1. **本雷达的 `_prefilter` 已经比较强**。它是确定性范围预筛，
   只丢「明显出局」的（排除主题 / 牵头机关不在白名单 / 事务性文件 /
   海外单个产品批准 / 正文 <100 字），其余留给 LLM。
   所以闸门在这里是**第二道**过滤，拦截率不会像 BD 雷达那么高。

2. **省级文件的误杀风险最高**。省级政策数量大、格式杂，
   象信如果把某条省级通知判成"非政策"，就会被误杀。
   观察期要**重点盯省级政策有没有变少**。

3. **象信仍不评分**。发文层级、影响范围、支付规则细节仍由 LLM 评。

4. **判据调优后拦截率从 25.1% 降到 18.9%**，这是正确的方向——
   拦得更少但拦得更准。宁可漏掉一些噪声送进 LLM，也不要误杀一条政策。

### 关于 CI 依赖（重要）

`xiangxin-sdk` **没有**写进 `requirements.txt`，而是在 workflow 里单独安装：

```yaml
- name: 安装象信可选依赖
  continue-on-error: true
  run: pip install "xiangxin-sdk>=0.3.2"
```

原因：闸门是可选增强，若把它当必需依赖，一旦 PyPI 抖动装不上，
会连带整条评分链路失败。装不上时闸门退回旁路，雷达照常跑。

### CI 上的密钥

`XIANGXIN_API_KEY` 需要写入 GitHub Secrets。
`radar.yml` 的「LLM 评分」步骤已注入该环境变量。

**没配这个 secret 时闸门会自动旁路，不影响评分**。
